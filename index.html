How JP Would Improve This

Specific features I'd ship next — mapped directly to Strada's JD and stack.

🤖 Agentic AI / LLM Platform

Temporal Workflow Orchestration for Long-Running Claims
Insurance claims can span days or weeks across multiple systems. I'd wrap each claim workflow in a Temporal workflow with deterministic retry logic — if the FNOL agent fails mid-way through a coverage lookup, the workflow resumes exactly where it left off, not from scratch. Eliminates partial-state bugs that are extremely hard to debug in stateless LLM agents.
Evaluator-Optimizer Agent Loop for Response Quality
Strada handles 5M+ customer interactions. I'd add an evaluator agent that scores each AI response (accuracy, compliance, tone) before it's sent, and routes low-confidence responses to a human review queue. Same pattern I shipped at iMatr — reduced bad-output escape rate without manual spot-checks.

⚡ Real-Time & Data-Intensive

TanStack Query + Optimistic Updates for Claims UI
The JD specifically calls out TanStack experience. I'd replace fetch-on-navigate with TanStack Query — stale-while-revalidate for the claims list, optimistic updates when an agent resolves a task, and background refetch every 30s for live dashboards. Claims ops teams need sub-second feedback when an agent takes action, not full-page reloads.
Postgres Partial Indexes for Agent Task Querying
The agent task queue grows fast at 5M interactions. I'd add CREATE INDEX ... WHERE status = 'pending' partial indexes per status + insurer_id, plus a pg_notify trigger to push task updates over WebSocket without polling. Same pattern I used at iMatr on a comparable multi-tenant schema — cut query time ~40%.

🔧 Integrations & Platform

Insurance System Adapter Layer (AMS360, Applied Epic, Duck Creek)
Insurance carriers run wildly different legacy systems. I'd build a typed adapter layer in TypeScript — each integration implements a common InsuranceSystemAdapter interface (get policy, update claim, trigger endorsement), so the agent orchestrator never knows which backend it's talking to. New integrations ship as plugins, not core changes.
Customer-Facing Interaction Audit Trail
Insurance is heavily regulated — carriers need to show exactly what an AI agent told a customer. I'd build an append-only interaction_events table (no UPDATE/DELETE) with every agent message, decision, and system action linked to a session. Full replay for compliance audits without touching production data.

📊 Ops & Observability

Forward Deployed Engineer Dashboard
The JD mentions working closely with Forward Deployed Engineers and customers. I'd build an FDE-facing dashboard: per-insurer automation rates, failure modes, escalation heatmaps, and AB test results — so FDEs walk into customer calls with data, not gut feel. Built in React + TanStack Table for sortable, filterable views with zero backend changes needed.
